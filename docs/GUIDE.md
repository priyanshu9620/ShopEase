# ShopEase — the guide

Everything needed to run the app, run the lab, read the results, and (later) deploy to AWS.
Written so it works without any chat history. Only Docker is required on the laptop.

## 1. What this repo is

- **The app**: a MERN e-commerce site (RBAC, catalogue, search, filters, Braintree sandbox payments).
  `server.js` + `controllers/` + `models/` + `routes/` are the original app; `client/` is the React UI.
- **The lab**: `lab/` (nginx load balancer, Prometheus, Grafana, k6, the runner) + `experiments/`
  (one folder per system-design concept). Each experiment runs the same load against two "arms"
  (concept off / concept on) and reports what changed.
- **Infra (Phase 3+)**: `infra/` Terraform for 3 × EC2 behind an ALB, S3 + CloudFront.

## 2. Run the app

```bash
cp .env.example .env         # add Braintree sandbox keys (sandbox.braintreegateway.com → Settings → API → Keys)
make up                      # app :8080 + MongoDB + Redis
make seed                    # 5,000 products, 12 categories, admin@shopease.local/admin123, buyer@shopease.local/buyer123
open http://localhost:8080
```

- `GET /healthz` → `{status, version, replica, mongo, redis}` (503 if Mongo is down). Used by compose, nginx, the ALB and the runner.
- `GET /metrics` → Prometheus text (request histogram by route/status, cache ops, Node runtime).
- Cache is off by default. `CACHE_ENABLED=true make up` turns it on; responses then carry `X-Cache: HIT|MISS`.
- `make down` stops everything (data kept); `make nuke` also deletes the volumes.

## 3. Run the lab

```bash
make lab                     # app ×3 (1 CPU each) behind nginx :8081, Prometheus :9090, Grafana :3000
make lab-status              # containers + which replica answers through nginx
make k6 RATES=50,100,200 STEP_S=30     # ad-hoc load, prints per-route p50/p95/p99
```

Grafana: `http://localhost:3000/d/shopease-lab` (anonymous viewer; admin/admin to edit). The dashboard
is provisioned from `lab/grafana/dashboards/lab.json`, which is generated by `lab/grafana/build-dashboard.mjs`
(`make dashboard`). Top row: running experiment/arm, replicas, RPS, p95, errors, cache hit %, version,
then RPS by arm, latency by arm, errors, RPS per replica, p95 per route. One collapsed row per concept.

## 4. Run an experiment

```bash
make experiment E=01-caching                   # both arms, 1 run each (≈ 11 min)
make experiment E=01-caching ARGS="--repeats 3"  # medians of 3 — the numbers used in the README
make experiment E=01-caching ARGS="--quick"      # 3 short stages, ≈ 2 min, for demos
make experiment E=01-caching ARGS="--arm treatment"
```

What happens, per arm: stack up with the arm's env and replica count → reseed + flush Redis (cold start)
→ Grafana annotation "arm start" → optional `before` hooks → k6 ramp through nginx (`during` hooks fire at
their offset, e.g. kill a replica) → annotation "arm end" + shaded region → every manifest metric snapshotted
from Prometheus over the window → `results/<arm>-<n>.json`. Then the report generator writes `report.md`,
`charts/*.svg`, `results.json` and regenerates `experiments/index.html`.

How to tell arms apart while watching: the terminal banner, the Grafana "Running now" stat (experiment / arm),
the `arm=` legend on every line, and the shaded regions tagged with the arm.

Manifest format and how to add a concept: `experiments/README.md`.

## 5. Read the results

- `experiments/<id>/report.md` — question, concept, headline table (baseline vs treatment, % change), charts,
  k6 client-side view, "what this does not prove", reproduce commands.
- `experiments/index.html` — one card per experiment. Published to GitHub Pages by CI on push to master
  (repo Settings → Pages → Source: GitHub Actions, once).
- Raw: `experiments/<id>/results/*.json` (git-ignored) — the Prometheus series and k6 summaries per run.

## 6. CI/CD

- `.github/workflows/ci.yml`: on every push/PR builds the image, smoke-tests `/healthz` against a real Mongo,
  and pushes `ghcr.io/priyanshu9620/shopease:<branch>-<sha>` (+ `:latest` on master).
- `.github/workflows/deploy.yml` (master only, needs the AWS stack up): builds `linux/amd64`, pushes to ECR
  `:<sha>` + `:latest`, publishes the React build to S3 + invalidates CloudFront, then rolls the EC2
  instances one at a time: deregister from the ALB → drain → `deploy.sh <sha>` via SSM → register → wait
  healthy. Measured: 247/247 outside probes OK during a roll.
- Secrets in GitHub: `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` (the scoped deploy user from `infra/`),
  variable `AWS_DEPLOY_ENABLED=true`.

## 6b. AWS (Phase 3/4) — `infra/`

Everything is OpenTofu in `infra/` (see `infra/README.md` for the diagram and the what/why of each resource).
Region `ap-southeast-2` (the account is region-locked); profile `shopease` in `~/.aws/credentials`.

```bash
cp infra/terraform.tfvars.example infra/terraform.tfvars   # secrets → SSM Parameter Store
make infra-plan && make infra-apply      # ~5 min (CloudFront is the slow part); prints alb_dns, cdn_url
# push to master (or re-run the deploy workflow) → image + client published, instances rolled
make aws-migrate-photos                  # existing photos → S3 (photoUrl set); /product-photo 302s to the CDN
make aws-bench ARM=cached ; make aws-bench ARM=uncached ; make aws-report   # experiment 10 (k6 on the loadgen)
make cdn-bench ; make k6-report E=11-cdn # experiment 11 (k6 on this laptop: ALB vs CloudFront)
make infra-destroy                       # ALWAYS at the end of a session (~$0.12/h while up)
```

Cost while up ≈ $2.6–3/day (3 × t3.micro, t3.small data, t3.small loadgen, ALB, CloudFront pennies),
covered by the free-plan credits. Nothing is left running between sessions.

Operational notes learned the hard way (details in the notes' PROBLEMS log): run load generators on
their own instance, never on the data box; burstable instances need `cpu_credits = "unlimited"` for
benchmarks; cap Mongo/Redis memory on a 2 GB box; keep the app's Mongo pool small (20); `deploy.sh`
re-reads SSM params, so toggling `/shopease/CACHE_ENABLED` or `/shopease/PHOTO_STORAGE` + redeploy
switches behaviour without a new image.

## 6c. Real-time and CDN (Phase 4)

- **Order tracking**: the Orders page opens a WebSocket (`socket.io`, JWT in the handshake). When an admin
  changes an order's status the row updates live. The Redis adapter relays the event between replicas;
  experiment 12 shows 3 replicas without it lose ~2/3 of updates.
- **Photos**: with `PHOTO_STORAGE=s3` new/updated photos go to S3 and `GET /product-photo/:pid` redirects
  to CloudFront; the React client is unchanged. `scripts/migrate-photos-to-s3.js` moves old ones.
- **React build**: served by CloudFront from S3; `/api/*` and `/socket.io/*` go to the ALB origin.

## 7. Troubleshooting

| symptom | cause / fix |
|---|---|
| `make lab` shows only 1–2 replicas answering | nginx re-resolves every 5 s; wait, or `make lab-status` again |
| Prometheus has no `app` targets right after start | DNS service discovery refreshes every 30 s |
| UI loads but every page errors | the React build must be same-origin: rebuild (`make up` does), see `client/src/index.js` |
| Braintree token 500 | wrong/missing sandbox keys in `.env` |
| experiment "stack did not become healthy" | `docker compose -p shopease ps`; usually Mongo still starting — rerun |
| Grafana shows nothing | time range: the dashboard defaults to last 15 min; annotations need the "lab events" toggle on |
| laptop git hooks complain | they come from a global template, not this repo; harmless (`.pre-commit-config.yaml` is ignored) |
